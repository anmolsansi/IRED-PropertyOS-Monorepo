## Start here

1. Read [repository context](REPO_CONTEXT.md) and [ticket standard](TICKET_DETAIL_STANDARD.md).
2. Check [coverage](ASSESSMENT_COVERAGE.md) and the dependency order below.
3. Assign one bounded ticket only after its dependencies/decisions are accepted.
4. Keep work in Pending until its own acceptance evidence is reviewed. Move accepted tickets to Completed and update the manifest/index.

The pack follows the AUTH-001 style: source evidence, mental model, explicit contracts, file boundaries, steps with checkpoints, detailed tests, manual verification, PR proof, rollback and completion record. New APIs/schemas are proposed designs. No new product behavior, paid provider, production migration or deployment is activated by these documents.

## Readiness and staged delivery

Start with independent SEARCH-001 and SEC-001 intake plus DEC-001/002/003/004/005 reviews. Tenant safety and data quality precede AI. Deliver confirmed requirements → deterministic matching → reviewed AI intake → immutable proposal delivery. Add owner grants and reviewed lease workflows in their own phase. Later cross-company exchange, workflow engines, external integrations and speculative AI require customer/architecture evidence before production implementation tickets are finalized.
